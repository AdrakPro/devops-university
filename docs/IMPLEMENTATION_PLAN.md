# Ubuntu 24.04 VM Pipeline — Implementation Plan

This plan implements the provided `solution.md` with the local
**Ubuntu 24.04.5 LTS** server ISO. The overall shape is unchanged:

1. Packer builds **one** base image.
2. Vagrant launches **three** VMs from that image on a host-only network.
3. Ansible configures each VM with a role.
4. Two hardening requirements are verified: UFW is enabled with role-scoped
   rules, and root SSH login is disabled.

## 1. Why the server ISO works

`solution.md` assumes Ubuntu Server with Subiquity `autoinstall`, and the
local ISO is exactly that: the Ubuntu **Server** edition ships Subiquity, so
`autoinstall` is supported natively. We drive it fully unattended:

1. Boot the live ISO.
2. Drop to the GRUB command line and boot with
   `autoinstall ds=nocloud-net;s=http://10.0.2.2:<port>/`.
   - `autoinstall` skips the "continue with autoinstall?" confirmation.
   - `ds=nocloud-net` tells cloud-init to fetch `user-data` and `meta-data`
     from Packer's HTTP server.
3. Subiquity reads the `autoinstall:` block, partitions the disk, installs
   the server packages, creates the `vagrant` user with our SSH key, installs
   and enables `openssh-server`, grants passwordless sudo, and reboots.
4. Packer waits for SSH, cleans the image, and exports `base-ubuntu.box`.

All per-role configuration remains in Ansible.

## 4. Step-by-step implementation

Each step ends with a **manual commit** by the repository owner.

### Step 1 — Plan and project skeleton

- Add this plan, a root `README.md`, a root `.gitignore`, and a `Makefile`.
- No build artifacts or keys are committed.

Commit: `docs: add Ubuntu VM pipeline implementation plan`

### Step 2 — Host toolchain

- Run `scripts/install-devops-toolchain.sh` with `FORCE=1` for Packer,
  Vagrant and Ansible.
- Required minimums: Packer ≥ 1.7 (HCL2 `required_plugins` and
  `packer init`), Vagrant ≥ 2.3 (VirtualBox 7 support), Ansible with
  `community.general`.
- Ensure the `vboxnet0` host-only network can be created for
  `192.168.56.0/24`.
- Record the final versions in `docs/TOOLCHAIN.md`.

Commit: `docs: record verified host toolchain versions`

### Step 3 — Project SSH key

- Add `scripts/generate-keys.sh`: creates `keys/id_ed25519` (ed25519, no
  passphrase) if missing.
- Add `keys/` to `.gitignore`; never commit the private key.
- The build injects `keys/id_ed25519.pub` into the autoinstall user-data.

Commit: `feat: add project SSH key generation`

### Step 4 — Packer template and autoinstall data

- Add `packer/image.pkr.hcl`:
  - local ISO via `var.iso_url` with the pinned SHA-256;
  - `virtualbox-iso` source, BIOS boot, 20 GB dynamic disk;
  - `boot_command` that boots the live system with `autoinstall` and the
    NoCloud datasource pointed at the Packer HTTP server;
  - `ssh_username = "vagrant"`, project private key, long SSH timeout;
  - `vagrant` post-processor producing `base-ubuntu.box`.
- Add `packer/http/user-data.tmpl` and `packer/http/meta-data`:
  - `autoinstall` with `identity`, `ssh` (key-only), `storage: direct`,
    `packages` (python3-apt, ufw), `late-commands` (NOPASSWD sudo),
    `shutdown: reboot`.
- Add `scripts/build-box.sh` and Makefile targets; the script substitutes the
  public key into `user-data` before each build.

Commit: `feat: add Packer template and Ubuntu autoinstall data`

### Step 5 — Build and register the base box

- `make build` → `packer/base-ubuntu.box`.
- `vagrant box add base-ubuntu packer/base-ubuntu.box`.
- Validate with `vagrant box list`.

Commit: `feat: add base box build workflow` (only if scripts change;
the box itself stays gitignored)

### Step 6 — Vagrantfile and static inventory

- `Vagrantfile`: box `base-ubuntu`, `vagrant` user, project key,
  `insert_key = false`, three nodes with the IPs above, synced folders
  disabled, Ansible provisioner on the frontend with `limit = "all"`.
- `ansible/inventory.ini`: the same three hosts and private IPs.

- Allow TCP 22 **before** enabling the firewall.
- Default deny incoming, enable UFW.
- Set `PermitRootLogin no` in `sshd_config` with a `sshd -t` validation and
  reload sshd.

## 5. Packer build flow in detail

```
VirtualBox VM (NAT)
  └─ Ubuntu live ISO (BIOS)
      └─ GRUB command line:
          linux /casper/vmlinuz autoinstall ds=nocloud-net;s=http://10.0.2.2:<port>/ ---
          initrd /casper/initrd
          boot
          └─ cloud-init fetches user-data/meta-data from Packer's HTTP server
              └─ subiquity runs autoinstall:
                  ├─ partition /dev/sda (direct layout)
                  ├─ install server, openssh-server, python3-apt, ufw
                  ├─ create vagrant user + project key, passwordless sudo
                  └─ shutdown: reboot
                      └─ installed Ubuntu boots, sshd starts
                          └─ Packer SSH provisioner + shutdown
                              └─ vagrant post-processor → base-ubuntu.box
```

## 7. Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| GRUB keystrokes miss the menu | Tune `boot_wait`/`<wait>`; use `packer build -debug` and the VM console |
| NoCloud datasource cannot reach the HTTP server | Pin the Packer HTTP port; confirm the live system's NAT NIC comes up |
| Installer prompts despite `autoinstall` | Keep `autoinstall` on the kernel line; `interactive-sections: []` in user-data |
| Installer refreshes its snap from the store | `refresh-installer.update: false` in user-data |
| Guest additions absent in the base box | Disable synced folders; Vagrant uses SSH + netplan, not Guest Additions |
| Vagrant `private_network` with NetworkManager | Vagrant 2.4 has nmcli/netplan support; verify after `vagrant up` |
| Host runs out of disk | Free space before build; `.box` and VDI are gitignored |
| Ansible 2.10 unsupported on Ubuntu 24.04 | Upgrade Ansible in step 2; install `community.general` |
| `community.general.ufw` missing | `ansible-galaxy collection install community.general` |
